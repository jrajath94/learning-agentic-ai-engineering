Muse Code is Meta's coding agent

The subscription called Muse Code is not an Apple product and not the old game model. Meta shipped Muse Code in beta on 5 August 2026, powered by the Muse Spark family, with a terminal binary named muse. By 20 November 2026 the pricing page lists Spark 1.3 as well as 1.2 and 1.1. The docs page still says the default model string is muse-spark-1.2.

Read this before you subscribe

Contributor mode is the discount you pay for by letting Meta train on the prompts, code, files, context, and responses you send. The pricing page says Muse Code subscriptions default to Contributor mode, and that you can turn it off in settings. Standard Spark prices are $1.25 per million input tokens and $4.25 per million output tokens. Contributor prices are $0.10 and $0.20. For an engineer inside a bank, the default is the fact that matters. C38

What a chat window does not give you

  • Persistent background agents. Meta's launch post says specialized background agents stay active for the whole session, instead of being spawned per task, and they choose when to talk to the main agent. C35
  • An event log that can resume. Every model call, tool run, approval, and edit is appended. After a crash the agent resumes where it stopped. Meta calls the runtime replay-exact and restart-safe. C35
  • Bundled skills with teeth. /plan is an approval-gated plan. /grill stress-tests the plan. /goal works toward a stated objective. C35
  • A sandbox and approvals from the first run. The docs say both are on immediately. First launch asks whether to trust the workspace, which is what loads skills, rules, and hooks. C37
  • Headless CI. muse exec "..." with META_API_KEY. Interactive /login is the other path. C37
  • Workflows and session messaging, with caveats. Workflows coordinate parallel and staged work only when that build includes the engine and the rollout is on. Session messaging, for handoffs between live sessions, is macOS and Linux, not Windows. Voice input is also absent on Windows. C37
  • A protocol, not only a TUI. muse serve speaks a versioned session protocol. muse schema prints JSON schema. npm install @muse-code/sdk wraps it. C37

Three workflows in Meta's own writing

1. Plan, grill, then a goal

The bundled skills are the published inner loop. /plan stops for approval. /grill is the adversarial pass on that plan. /goal is the long run. Meta says Spark 1.2 was co-trained on this harness, including recipes for goals, compaction, and subagents. That is an argument for using the bundled skills rather than a novel prompt that fights the training. It is still Meta's argument. C35 C36

2. A day-long kernel optimization

Meta's case study: more than 1,000 tool calls, up to 24 hours, writing, compiling, and profiling GPU kernels against a baseline, on KDA and MLA kernels for NVIDIA Hopper. They say the agent kept improving on the baseline. The evaluation report linked from the post was not fetched, so the size of the speedup is not repeated here. The workflow shape is: a baseline, a profiler, a loop, a long event log. C36

3. Rebuild a page from a video, then check it in a browser

The launch post describes a demo in which an mp4 fly-through of a house goes into the terminal and Muse Code produces a booking page, then validates the site in a browser. Treat it as a product demo. The transferable piece is the last step: validation in a browser, not the luxury-rental subject. C35

Principles you can take without adopting the brand

  • Co-train the model with the harness you will actually run, or at least use the harness the model was trained in. Meta states they did the first. C36
  • A log you can replay is the state of the agent. Chat scrollback is a worse log because a crash throws it away. C35
  • Background agents that live for the session avoid re-gathering the same facts. That is the same idea as Claude's complaint that a fresh subagent must re-gather context, solved by persistence instead of by keeping everything in the main window. C18 C35
  • Compaction is how a long horizon fits. Meta lists it next to planning and goal conditioning as the way Spark 1.2 holds a whole-repo task. C36

Strongest counterargument

Adversarial

The interesting engineering posts are Meta evaluating Meta. The kernel study has no public patch and no third-party rerun in this ledger. The docs/pricing mismatch (default 1.2 versus a listed 1.3) means "latest model" is not a single string. And the subscription default sends your code to training unless you change a setting. A frontier-lab interview loop cares about the second fact more than about the kernel demo.

Tutorial · first session with training off and a plan gate

1. Question

How do I run Muse Code on a real repo once, with Contributor mode off, and stop after a plan I can read?

2. Facts

Installer, trust prompt, default model id muse-spark-1.2, /plan approval gate, Contributor mode default, standard versus contributor prices. C37 C38 C35

3. Concepts

Trusting the workspace loads skills, rules, and hooks. That is a capability grant, not a courtesy dialog. Contributor mode is a data grant. They are different switches and both default in the direction of more access for the tool.

4. Loop

  1. Trigger. You, in a checkout you can throw away.
  2. Execute. muse, sign in, turn Contributor mode off before the task, then /plan on one bug.
  3. Verify. Read the plan. Do not say go until it names the test. The approval gate is the product's own pause. C35
  4. State. If you continue later, the event log is what Meta says lets a crashed run resume. You still commit only what you have read. C35

5. Conflicts

Superpowers can also be installed as a Muse plugin (muse plugins install, then muse plugins approve superpowers). Superpowers says its workflows are mandatory. Muse's own skills are /plan, /grill, /goal. Running both means two planners. Pocock's README argues that frameworks which own the process take control away. Pick one planner for the week. C44 C43

6. Hypothesis unproven

Hypothesis

Spark 1.3 is the better coding default than the documented 1.2 string. The pricing page lists 1.3. The getting-started page still names 1.2. No changelog fetched here says 1.3 replaced 1.2 as the default. Check muse itself and the pricing page on the day you switch. G05

7. Decision support

  • You want Meta's harness and you can opt out of training: Muse Code, Contributor off, standard rates.
  • You are building your own agent and only need the model: the Model API, same price table, and you must pass muse-spark-1.3-contributor or muse-spark-1.2-contributor explicitly if you intend the cheap tier. C38
  • You need session messaging between live Muse sessions: macOS or Linux, and a build where the feature exists. C37
  • You want a design skill rather than a coding loop: Hallmark, which is a different author and works across harnesses. C45

8. Bounded next action

Install the binary. Before any task, open settings and turn Contributor mode off. Run /plan on a bug you already understand. Approve nothing. Compare the plan to the patch you would have written. That comparison is the evaluation.

  • What does Contributor mode grant Meta?

    Permission to use prompts, code, files, context, and model responses to train future models. Subscriptions default to it. C38

  • Which skill is the approval gate?

    /plan. /grill stress-tests the plan. /goal pursues the objective. C35
