Sequence and state

1. What he said

At 00:32:33: it runs sandboxed. A command that should run with additional permissions outside the sandbox asks the user. Every tool execution happens that way, in the captions' wording. At 00:33:19 he describes a cloud choice: a managed VM, the same VM you get through the chat product, in a kata container. At 01:01:41 he names slash goal for a run that keeps going, and says it was added a few months earlier. C304 C305.

2. Artifact

The sandbox key you can copy is still sandbox_mode = "read-only" in kit/codex/config.toml.sample. Slash goal is a command, not a new config key. The newsletter quote about deletions under full access with no sandbox is C295. His description here is the control that setup did not have.

3. Your stack

Keep the sample on read-only until a task names one directory. Do not turn on a mode that skips the ask, on a bank repo, because a course called the equivalent "yolo" on a different product.
