Tutorial · install one skill system and prove it loaded

1. Question

Which one repo should I install first, and how do I know the install worked without starting a two-hour autonomous run?

2. Facts

The five install blocks above. Pocock's duplicate-install warning. Superpowers' session-start bootstrap. Hallmark's "name it if it does not fire." pstack's two-step setup. Caveman's Node 22.13 requirement.

3. Concepts

A skill that does not load is an empty program. The description is the scheduler key. If you install three routers, you no longer know which program ran. The verification is a behavior you can see: a question asked before code, a plan that waits, a terse reply, a playbook name in the todo list.

4. Pattern

  1. Pick from the decision list in part 7. Install only that one, using the command for your harness.
  2. Open a fresh session. Compaction and already-open sessions are how Superpowers and Muse plugins fail to show their hooks. The Superpowers Muse note says to restart so SessionStart runs.
  3. Send the probe for that repo, from part 7.
  4. If the probe does not happen, stop. Do not add a second system to "make it work."

5. Conflicts

Hallmark's older reviews tell Cursor users to paste SKILL.md into .cursor/rules. The README fetched now says npx skills add and that Cursor finds the skill copies. Follow the README. Superpowers on Muse wants muse plugins approve. Skipping approve means the files are present and the hook is not.

6. Hypothesis unproven

Hypothesis

For a strong model in late 2026, Pocock's grill-first skill changes outcomes more than a mandatory full lifecycle, because the model already knows TDD and the human still does not know the requirements. His README argues the misalignment point. It does not include a head-to-head against Superpowers.

7. Decision support

  • You are about to be misunderstood. Pocock. Probe: /grill-me on a one-sentence feature. Success: it asks questions and does not edit.
  • You want a forced lifecycle and you accept the loss of control. Superpowers. Probe, from the Muse section of the README: send "Let's make a react todo list" and expect brainstorming before code. He offers that sentence as the verify step.
  • You are in Cursor and you want playbooks plus a multi-model review. pstack. Probe: /poteto-mode on a tiny bug with the words "repro first." Success: a playbook's steps show up as todos.
  • The bill is the problem. Caveman. Probe: ask why a React component re-renders. Compare length to an uninstrumented session. His own example answer is the short useMemo line. Do not install Auto until you have read the contributor-style account note in his README.
  • You are generating a new page and you hate the default look. Hallmark. Probe: /hallmark audit ./index.html on a page you already have. Success: a report, no silent restyle.

8. Bounded next action

Install Pocock's skills in the harness you use most, run setup once, and run /grill-me on the next change you have not started. Do not let it write code in that session. Write down whether the questions changed the task. That note is your eval.
