Codex and dots

A short AGENTS.md, a read-only sandbox, then a task.

The keys in config.toml.sample are copied from OpenAI's sample, fetched 20 Nov 2026. The git pointer that links to that page is openai/codex 4e9ce8fa9e7649ec58601a3d61da7a086da75500, file docs/example-config.md.

See the shape first

1. Mechanism

Codex reads config.toml for the model and the sandbox, and AGENTS.md for project rules. The sample sets project_doc_max_bytes = 32768. Past that cap, later instruction files are not added. Mert Ozen's 15 Nov 2026 walkthrough of the 0.169 docs says a closer file overrides an earlier one. Put the test command in the nearest AGENTS.md, not only in your home directory.

The sample sets sandbox_mode = "read-only" and approval_policy = "on-request". A task that must edit has to leave read-only on purpose. The sample model string is gpt-6.1-sol. The page says to replace it if your account does not have that model. CLI 0.171.0, released 20 Nov 2026, also lists Sol as the default catalog selection.

Claude Code 2.1.277, 18 Sep 2026, reads AGENTS.md when the project has no CLAUDE.md. One file can serve both tools if you keep it inside the byte cap. If CLAUDE.md exists, Claude may ignore AGENTS.md. Check /config.

2. Artifact

model = "gpt-6.1-sol"
model_provider = "openai"
approval_policy = "on-request"
sandbox_mode = "read-only"
project_doc_max_bytes = 32768

Full sample keys, including the commented reasoning lines, are in the kit file. AGENTS.md in the kit is a short synthesis, not an OpenAI template. Dots, from the 29 Sep 2026 launch, can start a Codex task. That task counts against Codex usage. The conversation with the dot does not.

3. Worked example

This session did not run codex against a paid account, so there is no model transcript here. The local stand-in for the red step is the same script as the Claude page: sh kit/scripts/tdd-demo.sh. It fails, then passes, with no network. Use that output as the shape you want from Codex: a failure paste, then a pass paste, then a one-function diff.

mkdir -p .codex
cp kit/codex/config.toml.sample .codex/config.toml
cp kit/codex/AGENTS.md AGENTS.md
# edit the test command, then:
codex

Paste kit/prompts/tdd-loop.md. If Sol is rejected, change model and start again. Do not keep a session that is on the wrong model.

4. Failure modes

  • sandbox_mode = "read-only" and a prompt that says "edit the file". The run stops or asks. That is the sample working. Switch mode only for the directory you mean to change.
  • AGENTS.md over 32 KiB. The sample's cap drops the rest. Split by directory.
  • A global AGENTS.md that says npm and a repo that uses pnpm. The closer file wins only if it exists and fits.
  • A dot that "improves the app" with no test command. The launch post's happy path is not a constraint. Put the test in the task.
  • Full access, no sandbox, no auto review. Firas D's 23 Jul 2026 newsletter quotes Thibault Sottiaux, dated there as 16 Jul 2026, on GPT-5.6 deletions that most commonly happened in that setup, including a HOME override that then deleted HOME. The quoted post was not opened. The sample's sandbox_mode = "read-only" is the control that setup did not have. C295.

5. Exercise

Copy the sample into a scratch repo. Set model to one you can open. Ask Codex to print the test command from AGENTS.md and not to edit. Self-check: the reply quotes your command, and git status is clean.

6. Your stack

Codex is the about $100 seat. Claude Code is the about $20 seat. Give both the same AGENTS.md test line. Use Claude for the plan when you want the TDD skill file loaded. Use Codex when you want the sandbox key enforced in toml. Do not send a bank ledger through a dot's browser. Production changes stay on a read of git diff by you.
