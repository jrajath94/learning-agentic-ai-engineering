Codex and dots

"Dots" is not a nickname for config files. OpenAI's dots are always-on ChatGPT agents with their own computer. Codex is the coding product they can delegate to. The CLI build fetched for this page is 0.171.0, released 20 November 2026, with GPT-6.2 Sol as the default catalog selection.

See the shape first

Verdict on dots

The launch post is dated 29 September 2026. An update on the same page, 3 November 2026, adds GPT-6.1 Terra. The original post says dots are powered by GPT-6 Astra and can draw on different models for different parts of the work. They have a cloud computer and browser, plugins to more than 4,000 apps, and channels in ChatGPT, Slack, and Teams, with texting described as coming later. C28

OpenAI's own comparison, echoed on the learn site: Chat is for an answer in conversation. ChatGPT Work is a delegated task such as research or a file. Codex is for building, debugging, testing, and reviewing software. A dot is for an ongoing responsibility that follows up between conversations and can delegate to Work or Codex. C29

There is a second, older meaning of "dot" in the Codex CLI: the home directory ~/.codex and config.toml. Mert Özen's November walkthrough uses that directory. It is configuration, not the product named dots. Both meanings are real. The product is the one OpenAI capitalized a launch around. C33

Codex CLI 0.171.0

GitHub release rust-v0.171.0, published 20 November 2026, matches the ChatGPT changelog entry of the same day. New in that release: GPT-6.2 Sol and Astra in the model catalog, Sol as the default catalog selection; the TUI workspace on by default, with document previews, image previews, and subagent transcripts beside the conversation; codex exec --remote; /rc and /remote for local remote control and device pairing codes; custom MCP status lines through /statusline when the flag is on. What regular users miss

  • The dot is not the coding agent. Asking a dot to "build the feature" is supposed to become a Codex task, which then counts against usage. Talking to the dot does not, according to the launch post. C29
  • Proactive research is read-only. When you are not actively working with it, the dot looks for ways to help using tools that cannot send, change app content, or control your browser or computer. Writes go through auto-review, Custom Rules, and, for some actions, you. Changing a password stays with you. C29
  • You can open the dot's computer. The launch post says you can inspect its work, and you can optionally connect your own laptop. The default is a separate machine. C28
  • AGENTS.md is a chain, not a single file. Özen, citing the docs for CLI 0.169.0 on 15 November, describes a global file, then one file per directory from the repo root down, closer file later, and a default 32 KiB cap after which further files are dropped. Nested instructions are the documented way to stay under the cap. C33
  • Skills are paged. A skill is a folder with SKILL.md. Codex ships skill-creator and skill-installer. Discovery paths he reports: .agents/skills walking up to the repo root, and ~/.agents/skills. The model first sees name, description, and path, with a default budget of 2% of the context window. C33
  • Remote control from the TUI. /remote and codex exec --remote are in 0.171.0. That is the "my session is not stuck on this laptop" path for Codex itself, distinct from a dot. C32

Three workflows

1. A dot watches feedback and opens Codex PRs

OpenAI's developer scenario: the dot watches customer feedback for recurring requests, scopes smaller fixes, builds and tests them, and brings complete pull requests with videos. You keep building the next feature. This is a launch-post scenario. No repository is named. C28 C31

2. Invoice caught between conversations

The same post says an early tester's dot noticed a missed invoice, prepared it, and sent it after approval. The tester is unnamed. Confidence on this as a business result is low. The permission shape is the part you can copy: prepare, then wait. C31

3. Teach the repo with a chain of AGENTS.md files

Thibault Sottiaux (GitHub tibo-openai) merged the AGENTS.md discovery guide into openai/codex on 19 October 2025. Özen's later walkthrough says the closer file wins and the global file affects every repo, so a project rule does not belong only in the global file. Put the rule next to the code it governs, and keep the combined text under 32 KiB or raise the cap on purpose. C34 C33

Strongest counterargument

Adversarial

Dots and Duet launched as the same shape: a proactive cloud computer that nags you. OpenAI's evidence that this produces shipped software is a paragraph of internal color and one anonymous invoice. The engineering substance that survives that skepticism is the CLI release, the AGENTS.md chain, and the usage split between chatter and delegated Codex tasks. If you only remember one control, remember that delegated coding still spends your Codex allowance.

Tutorial · a repo Codex can enter without a novel

1. Question

How do I set up one repository so Codex CLI 0.169 or newer follows local rules, finds a skill only when it is relevant, and can be reviewed by me before anything merges?

2. Facts

Instruction chain and 32 KiB cap, skill paging at about 2% of context, Sol as the 0.171.0 catalog default, and the rule that a dot's Codex tasks consume usage. Özen's post is secondary; the CLI release is primary. C32 C33 C29

3. Concepts

AGENTS.md is the resident manual. A skill is a program you do not map into RAM until the description matches. The 2% budget is why a 40-skill "load everything" repo makes the model worse at the skill you wanted: the index itself is the cost. Config in ~/.codex is yours; a dot is a different product that may call this CLI's cloud cousin.

4. Loop

  1. Trigger. You, or a dot you have told to open a Codex task.
  2. Execute. Codex reads the chain from root to working directory, then the skill index.
  3. Verify. You read the diff. Auto-review on a dot is not a substitute for that read. Password changes and other sensitive actions stay human even in the dots design. C29
  4. State. When a rule was ignored because it lived in a global file and a closer file contradicted it, move the rule down the chain. Özen's reading of the docs says the closer file wins. C33

5. Conflicts

People say "dotfiles" and mean ~/.codex. OpenAI says "your dot" and means an agent. Using one word for both will make a runbook dangerous. Also, Özen checked 0.169.0 on 15 November. 0.171.0 shipped five days later. The release notes fetched here do not say the AGENTS.md chain changed. They also do not repeat the 32 KiB number. Treat the cap as secondary until you confirm it on your build.

6. Hypothesis unproven

Hypothesis

A dot that only opens Codex tasks for bugs with a failing test in the prompt will outperform a dot allowed to "improve the app." The launch post describes the happy path and does not test the constraint. The constraint matches Anthropic's documented bug prompt, which is a different vendor. C19

7. Decision support

  • You are editing code now: Codex CLI or the Codex app, not a chat with a dot.
  • You want something remembered across days and handed to Codex when it becomes code: a dot, on a plan and in a region that has it. First dot included for Pro and Business Premium in the launch post. C30
  • You want a methodology inside the CLI: Pocock's skills or Superpowers, installed for Codex specifically. Pocock warns that installing both the plugin and a skills.sh copy duplicates every skill. C43

8. Bounded next action

In one repo, add a root AGENTS.md of under half a page: how to test, which directory not to edit, and what "done" means. Run a single Codex task that must cite that file's test command in its final note. If it cannot, the chain is not being read, and adding more skills will not fix it.

  • Do conversations with a dot spend ChatGPT usage, according to the launch post?

    No. Codex or ChatGPT Work tasks that the dot starts do. C29
