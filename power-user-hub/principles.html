Harness model

Context is RAM. Tools are syscalls. Skills are programs. Evals are verifiers.

This mapping is a teaching frame. Each box is tied to a sentence a vendor or an author actually published. Where the frame goes past those sentences, it says so.

See the shape first

Context is RAM

What sits in the window is what the model can address this turn. Anthropic's skills docs say the body of a skill stays out until the task needs it, while CLAUDE.md is resident. Codex, in Özen's reading of the docs, shows the model only a skill's name, description, and path, inside a default 2% budget, and drops AGENTS.md content past 32 KiB. MCP's July 2026 spec adds cache hints and a stable list order so a tool catalog does not bust the prompt cache on every reconnect. pstack tells you to keep descriptions short enough that the router fits. C18 C33 C39

Subagents are a second address space. They return a summary so the search log does not stay resident. The cost is that they re-fetch what the parent already knew, which is why Muse's persistent background agents are an alternative design: keep the worker's RAM warm for the session. C18 C35

Caveman is a compressor in front of that RAM. The author is explicit that a one-line "be concise" instruction already does much of the output cut. Compression of tool output is the larger claim, and it is his measurement. C46

Tools are syscalls

A tool call is the model leaving its address space. The harness decides whether the call is legal. Anthropic draws that line in a table: the model may choose; the hook, the deny rule, and the sandbox must run. Grok Bot 1.2.3 makes the same idea visible as four levels on every connector tool. Duet and dots put a human ack on send, pay, sign, and delete, and they name a few calls that are illegal even with an ack. MCP tools are the portable syscall table, authorized with a bearer token on every HTTP request when you use the HTTP spec, or with environment credentials for stdio. C17 C06 C12 C40

A prompt that says "never send" is a comment above the syscall. The permission level is the syscall filter. Use both, and do not pretend the comment is the filter.

Skills are programs

A skill is a folder with a name, a description the scheduler matches, and a body that is the program. Claude Code, Codex, Cursor, Muse, and the npx skills installer all speak variants of that shape. C20 C33 C43

Programs differ in how hard they seize the scheduler:

  • Pocock: small programs you invoke, especially /grill-me before you let anything else run. He argues against a framework that owns the process. C43
  • Superpowers: a program that runs at session start and insists on its sequence. C44
  • pstack: one router, /poteto-mode, which selects a playbook and calls the other programs. C47
  • Muse: three builtins, /plan, /grill, /goal, co-trained with the model. C35
  • Grok: save a demonstrated task as a skill and schedule it. C03
  • Hallmark: a program that refuses to run on an existing design unless you name it, because the author does not want it restyling a system you already have. C45

Evals are verifiers, and the author is not one

Anthropic's table puts "Claude's summary of what it did" in the column the model controls, and "a person who approves the merge" in the column the harness and the org control. Superpowers names verification-before-completion and deletes implementation that preceded a failing test. pstack's interrogate drops findings that a run does not prove. Boris's January practice had a browser extension iterate until the UI matched. Meta's kernel study used a profiler against a baseline, which is a verifier even though the study is Meta grading Meta. Karpathy's vibe-coding description is the negative example: no read of the diff, so no verifier. C49 C44 C48 C22 C36 C41

A second model is a verifier only if it can falsify the claim. A second model that rewrites the patch is another author. /btw in Antigravity is documented as read-only, which is the right shape for a question that must not become a second author mid-flight. C25

Trigger, execute, verify, state

The loop is the operating discipline that falls out of the four boxes. The stack page maps it onto each product. In one line: something starts the run, the model spends a bounded context calling tools, a check that the model does not grade itself decides whether the run counts, and a durable store (git, CLAUDE.md, AGENTS.md, an event log, a skill) changes so the next run is not amnesiac.

Skipping state is how teams re-teach the same mistake. Boris's team wrote the mistake into CLAUDE.md during review. Pocock's grill-with-docs writes the noun into a glossary. Muse writes the trace into an event log so a crash is not a forgotten lesson. Those are three stores. Pick the one your harness actually reloads. C22 C43 C35

Graph thinking

A task is a graph of decisions and file writes. Sequential edges are data dependencies: the test's shape depends on the plan, the patch depends on the failing test. Parallel edges are slices with no shared write. The products that grew up in 2026 all grew a primitive for the parallel edges: subagents, swarms, background agents, separate checkouts, message boards. They also grew a primitive for the sequential edges: plan mode, /plan, Orchestrator, brainstorming-before-code.

The failure mode is scheduling a parallel primitive on a sequential edge. Five agents in one checkout, which Boris avoided. A swarm editing one module. Three proactive agents drafting the same email. The fix is to draw the edge before you pick the primitive. That drawing is the plan.

Self-test

  • Name the resident set and the paged set in Claude Code.

    CLAUDE.md is resident. Skill bodies are paged. Subagent transcripts stay in the child; the parent keeps the summary. C18

  • Which of these is a syscall filter: a CLAUDE.md sentence, a Grok tool set to Blocked, a skill description?

    The Blocked tool. The other two are instructions and scheduler hints. C06

  • Why is the model's "done" not an eval?

    Anthropic puts that summary in the non-deterministic column. An eval is a test, a hook, a prover run, or a person with merge rights. C49
