Gemini CLI and Antigravity

Put the test command in GEMINI.md. Do not paste the CLI repo's build script.

The upstream file is GEMINI.md in google-gemini/gemini-cli at addc194f5bc414e7134c2bd6a414a40e1b4cbbed. Lines 1-65 are in the excerpt, from commit addc194f5bc414e7134c2bd6a414a40e1b4cbbed. Sequence and state

1. Mechanism

Gemini CLI loads GEMINI.md as project context, the same job as CLAUDE.md. The upstream file lists Node 20, npm run build, and nightly memory tests that it tells contributors to skip unless they are changing those tests. The mechanism is: the file is resident context, so a command in it will be run. A command for the wrong repo wastes the turn and can delete the wrong tree.

Antigravity, changelog 18 Nov 2026: Orchestrator (Neon) plans with Gemini 4 Neon and implements with Gemini 4 Hydrogen. /btw as of 16 Nov 2026 is a side question with read-only tools. /swarm coordinates subagents on a message board. None of those read GEMINI.md from the CLI repo. There is no Antigravity settings file with a commit SHA in this kit.

The Antigravity Team's 12 Nov 2026 post says Orchestrator pairs Hydrogen with Carbon, and that on Terminal-Bench 4.1 it reached near-Carbon success while using 24 percent less quota and finishing 19 percent faster, on average. Hydrogen alone, the post says, scored 51 on the Artificial Analysis Intelligence Index, 54 at the highest setting, and 57 percent on Terminal-Bench 4.1 against 18.2 percent for 3.8 Flash. Four levels: low, medium, high as default, and xhigh. Those are the vendor's figures. Hacker News item 50472260 had 509 points and links the post. It is not a second run. C283 C284.

2. Artifact

kit/gemini-antigravity/GEMINI.md is a short file with placeholders. The turn that only prints the test command is kit/prompts/gemini-one-command.md. Copy the markdown file. Read the excerpt so you can see what not to copy: npm install, npm run build, npm run preflight, npm run test:memory, and the @google/gemini-cli-core workspace path.

3. Worked example

cp kit/gemini-antigravity/GEMINI.md GEMINI.md
# set TEST_COMMAND to the command you already use
# bad: npm run preflight
# bad: npm run build
# those two are in the gemini-cli GEMINI.md, not in yours
# good: python3 -m unittest tests.test_auth

This pass did not launch the Antigravity GUI. The sequence the changelog supports is: one prompt, Orchestrator if you want Neon to plan and Hydrogen to edit, then you read the diff. A read-only check goes to /btw, not a second editing agent.

4. Failure modes

  • Pasting the upstream GEMINI.md into a Python repo. The agent runs npm install.
  • /swarm on two tasks that edit the same module. The changelog does not serialize that for you.
  • Assuming Google AI Pro includes Carbon. The 18 Nov note lists Neon on Pro. Carbon's consumer row was not extracted. See the gap report.

5. Exercise

Write a three-line GEMINI.md whose only command is one you run by hand today. Ask the CLI to print that command and not to run it. Self-check: the reply matches the file, and the process list shows no npm.

6. Your stack

Google AI Pro is the seat for Antigravity and Gemini. Use it for the plan and implement split. Keep the test command identical to CLAUDE.md and AGENTS.md so a review on Claude or Codex checks the same thing. Do not put production customer paths in GEMINI.md.
