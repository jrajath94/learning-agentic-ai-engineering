Claude, Claude Code, and Claude Duet

Claude Duet is real. It is a research-preview app, opened 23 October 2026, in which Claude comes to you. Claude Code is the coding harness: skills, hooks, subagents, and a documented split between advice the model may ignore and rules the harness enforces.

See the shape first

What Duet is

Anthropic's 23 October 2026 article opens a waitlist for US Pro, Max, and Ultra subscribers. Duet is a standalone app on iOS, Android, and claude.ai, separate from the main Claude app during the preview. It uses the plan's usage limits. It is built around Claude Opus 5.5. C11 C12

The help center adds limits a launch headline leaves out: you cannot pick a model; Team and Enterprise are not in the preview; it cannot see all of your projects or the files on your computer; it cannot show you its browser; Personal Finance is unavailable. Finished files show up in a Make tab. C16 C13

It checks connected accounts every few hours, because continuous checking would burn the plan faster. Before send, pay, sign, or delete, it is supposed to show you the action and wait. Trading securities and moving money stay off-limits even if you approve. C12

What regular users miss

  • Deterministic versus non-deterministic. A prompt, CLAUDE.md, and a skill are advice. A hook, a deny rule, or a managed setting is the harness. If you keep adding emphasis and the model still misses the line, Anthropic says that line belongs in a hook. C17
  • Skills instead of a bloated CLAUDE.md. The name and description sit in context; the body loads when the task needs it. A release procedure in CLAUDE.md taxes every unrelated bugfix. C18
  • Subagents as context management. Use them for parallel slices, for noisy test logs, and for a reviewer who did not watch the code get written. They spend the same usage budget, and a fresh subagent re-gathers context, so they can be slower. C18 C20
  • A check that defines done. Tests, typecheck, a Stop hook, CI. The model's own summary is the non-deterministic column. Branch protection and a person approving the merge are the last word. C21 C49
  • Specific prompts. Name the symptom, the file, and what fixed looks like. "Be ambitious" is documented as a scope hint, because the model otherwise builds the smallest thing that satisfies the ask. "Think step by step" does not raise the effort level. C19
  • Duet for work that is not a repo. Morning brief, a cloud VM, marketplace connectors Anthropic counts above 6,000. Coding stays in Claude Code unless you are handing Duet a stated task such as a prototype. C13

Three source-grounded workflows

1. Boris Cherny, 2 January 2026, coding

From his own post, mirrored on Thread Reader and echoed by InfoQ. He described the setup as surprisingly vanilla.

  1. Five local terminal sessions, each its own git checkout, plus five to ten on claude.ai/code. Hand off with &, move with --teleport, start some from the phone.
  2. Plan mode until the plan is one he likes. Then auto-accept edits. He wrote that a good plan lets Claude one-shot the PR.
  3. A shared CLAUDE.md in git, about 2.5k tokens, updated when Claude does something wrong. He tagged @.claude on coworkers' PRs.
  4. Slash commands for the inner loop, including /commit-push-pr, with inline bash so the command does not spend a turn rediscovering git status. Subagents for simplify and for end-to-end verify.
  5. A PostToolUse hook running the formatter. Permissions pre-allow safe commands. --dangerously-skip-permissions only inside a sandbox for long tasks.
  6. Verification: Claude drives the Chrome extension against claude.ai/code and iterates until the UI works. He called the feedback loop the difference of a factor of two or three, in the InfoQ echo of the thread.

Strongest counterargument

Adversarial

The January post is the best public coding diary in this cluster, and it is ten months old relative to Duet and Opus 5.5. The October business stories are selected quotes with no artifacts. A bank engineer should not treat "ship code with Duet" or "110 employees on Duet" as a procedure. The durable, still-current document is the best-practices page: put facts Claude cannot see into CLAUDE.md, put procedures into skills, put non-negotiables into hooks, and do not let the model certify its own PR.

Tutorial · plan, implement, and refuse self-certification

1. Original question

How do I get Claude Code through a real bugfix without trusting the sentence "done"?

2. Facts

  • Anthropic's rewrite of a vague bug prompt names the symptom, the directory, a failing test, and then the fix. C19
  • Plan-then-auto-accept is Boris's January practice, not a 20 Nov 2026 guarantee. C22
  • A Stop hook or CI is deterministic. The model's summary is not. C49
  • A reviewer subagent has not watched the code being written. C18

3. Concepts

Context is the RAM of the session. Stuffing the whole release runbook into CLAUDE.md is a resident program you never page out. A skill is a program loaded on demand. A hook is a syscall the model does not get to skip. The verifier is a test or a second context, not the author of the patch.

4. Loop

  1. Trigger. A failing test or a user report you can point at.
  2. Execute. Plan mode until the plan names files and the test. Then let it edit.
  3. Verify. The new test fails before the fix and passes after. A subagent reviews the diff without the implementation transcript. You read the diff.
  4. State. If the model repeated a project-specific mistake, add one line to CLAUDE.md or, if it must always happen, a hook. Boris's team did the CLAUDE.md half in git. C22

5. Conflicts

Best practices say current models often do the right thing with a plain first prompt, and also say a specific prompt saves a round of corrections. Both can be true: the plain prompt is enough when the repo contains the constraint; the specific prompt is for the constraint that is only in your head. Parallel sessions need separate checkouts, which is what Boris wrote, because one working tree shared by five agents is a race.

6. Hypothesis unproven

Hypothesis

A reviewer subagent on a different model family catches more "works on my run" bugs than a second pass by the author model. Anthropic documents the fresh-context benefit. They do not publish a cross-family ablation in the page fetched here. pstack's default panel is one public recipe for the cross-family version. C47

7. Decision support

  • Claude Code when the artifact is a diff in a repo you can test.
  • Duet when the artifact is a brief, a draft, a deck, or a calendar catch, and you can tolerate a research preview that will not show its browser.
  • Skip Duet for Team or Enterprise accounts until the help center says otherwise. C16

8. Bounded next action

Take one known bug. Prompt with the symptom, the directory, and "write a failing test that reproduces it, then fix it." Do not accept the patch until you have seen the test fail for the old reason. That is the whole exercise.

Worked example

users report login fails after the session times out.
look at token refresh in src/auth/,
write a failing test that reproduces it, then fix it

That text is Anthropic's documented example, not a prompt from a private log. C19
