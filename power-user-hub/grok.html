1. Mechanism

A Bot has a cloud computer, but the changelog prefers a connector to the browser when a connector exists. Permissions are per tool, not per connector. Search can be Always allow while send is Needs approval. Auto-review means xAI's checker decides whether you see the action. Needs approval means you see it every time. A routine that loses its sign-in skips until you reconnect. It does not keep sending.

2. Artifact

kit/grok-bot/README.md is the setup order. The prompt forbids send, pay, post, and delete. xAI's own Gmail example also leaves drafts unsent. That example is product copy, not a customer's log.

3. Worked example

No Grok Bot session was run from this environment. The steps you can perform in the product are numbered in the kit README: one mailbox, two different permission levels, one pass, zero sends. If a reconnect card appears, the 1.2.3 notes say the routine will skip. That card is the output you are looking for when auth dies.

4. Failure modes

  • Auto-review on send. You wanted a card every time. Auto-review can let a send through.
  • Three bots on one inbox. The docs show handoffs as a storyboard. They do not show what happens when two bots draft the same thread.
  • Scheduling a routine after one bad draft pass. Save the skill only after you would have sent the draft yourself.

5. Exercise

Connect a mailbox you can afford to clutter with drafts. Set send to Needs approval. Run the kit prompt for one day of mail. Self-check: the sent folder has nothing new from the bot, and you can point at one draft that used a fact from the thread.

6. Your stack

Grok Bot is the desk tool, not the repo tool. Code still goes through Claude, Codex, Muse, or Antigravity, with a test command. Do not ask the Bot to edit a production service. A bank inbox should not be on Always allow for send, even if a vendor demo looks faster that way.
