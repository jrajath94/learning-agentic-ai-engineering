Five tabs, plan mode, then a person still merges.

Boris Cherny told Gergely Orosz how he was shipping that week. The transcript used here is SozAI's mirror. The same clock times appear on usetranscribe. The episode page is newsletter.pragmaticengineer.com. He said copying his setup as the one correct way is the wrong conclusion.

See the shape first

1. Why the harness can do this

At 33:32 he says Claude Code is built to be hackable because no two engineers share a workflow. Plan mode is a harness state, not a magic word: Shift+Tab twice in the terminal, and the model is not supposed to edit yet. Parallel tabs only work if they do not share a working tree. A checkout per tab is one way to get that. The desktop app's worktrees are another: git stores the extra trees cheaply and the app creates them so he does not run git worktree himself (34:27 to 35:33).

At 42:19 he says Claude started launching itself in a bash subprocess to ask whether it still works. That was not a feature they coded as a special case. It showed up with Opus 4.5. The CI piece is separate: the Claude agent SDK, which he calls Claude-P, reviews every pull request. He estimates it catches about 80 percent of bugs. Some comments it fixes. Some it leaves because it is not sure. A person still approves (about 42:19 to 45:59 in the usetranscribe copy).

2. The artifact

He did not paste a config file on this episode. The steps he named are the artifact. The prompt you can paste is kit/podcasts/pragmatic-boris-plan-round.md. It is marked original synthesis. It is not his prompt.

Commands he named:

  • Plan mode: Shift+Tab twice.
  • New codebase: /config, output style, explanatory rather than learn. He said explanatory tends to be better when you do not know the repo yet (37:28).
  • Known codebase: plan mode, then one-shot the implementation once the plan is right. He said Opus 4.5 got there and 4.6 does it more reliably (38:00).
  • Review fan-out: tell it to start three agents, then parallel dedupe agents for false positives. He said the internal review skill is open source in the Claude Code repo. This pass did not open that file, so the skill body is not copied here.
  • Cloud environment: a SessionStart hook. The hook body was not read out.

3. Worked sequence

This is the order he described. It is not a log from his machine.

  1. 33:50. Five terminal tabs. Each tab is its own checkout of the repo.
  2. 34:04. Start Claude in plan mode in tab 1. Give it the task.
  3. 38:15. While tab 1 plans, start tab 2 in plan mode on a different task. Then tab 3 and tab 4.
  4. 38:27. When a notification says a plan is done, read it. Go back and forth until the plan is one he accepts. Then it usually one-shots the edit.
  5. 34:27. When he runs out of terminal tabs he uses the desktop app, which makes the worktrees.
  6. 35:42. In the morning he starts a few agents from the iOS app. They run in the cloud. He guessed, without pulling the data, that something like a third to a half of his code starts on the phone (36:15).
  7. 42:19. On a Claude Code change, the model launches itself in bash and checks that it still runs. CI then reviews the PR. A person merges.

At 0:00 in the usetranscribe copy he says he was writing maybe 10 or 20 pull requests a day and that Opus 4.5 plus Claude Code wrote 100 percent of those, with no manual line edits. The SozAI show notes say 20 to 30. He also says Claude Code writes something like 80 percent of the code at Anthropic on average (30:37). Those are his estimates, not a dashboard screenshot.

4. Failure modes

  • Two agents, one checkout. He spends the episode on isolation because the agents otherwise collide. If your second tab is the same directory, you are not doing his workflow.
  • Plan mode skipped. He says the one-shot happens after the plan is good. A vague first prompt burns the tab.
  • Learn mode on a repo you already know. He reserves explanatory for onboarding. On a familiar repo he wants shipping, not a tutorial.
  • CI review treated as the merge. He says about 80 percent, and a person still approves. The other 20 percent is the point of reading the diff.
  • Phone session with no environment hook. He says the cloud task needs the environment configured, and they use a SessionStart hook because their environment is simple. A bank repo with private indexes will not boot from an empty cloud VM.

5. Exercise

On one of your repos, pick two bugs that do not touch the same files. Open two clones, or two worktrees:

git clone {{REPO}} /tmp/task-a
git clone {{REPO}} /tmp/task-b
cd /tmp/task-a

Paste the kit prompt with a real test command. Stay in plan mode until the plan lists files. Only then say go. Repeat in /tmp/task-b while the first plan runs. Self-check: git diff in task-a does not contain task-b's files, and you ran the test yourself.

6. His stack, and yours

He is on Claude Code inside Anthropic, including the desktop app and the phone's cloud tab. Your Claude seat is the about $20 plan you reported, not their internal build. Five long Opus sessions will hit that cap faster than one. Codex at about $100 can take the second checkout if you want a different model family on the review, which this episode does not demonstrate. He does not describe Antigravity, Muse, or Grok Bot here.

For a bank repo: do not point the phone's cloud agent at customer data or production credentials. The SessionStart hook he mentions is for their simple environment. Yours should refuse secret files. The human merge he still requires is the control that matches a production change.

Where people disagree

  • Gergely, at 36:28, says he maybe runs two agents and likes to follow one tab, including learn mode. Boris says that mode is for a new codebase. After that he round-robins and does not stay inside one task.
  • Boris on 2 Jan 2026 told people he uses separate checkouts rather than worktrees. On 4 Mar 2026 he still describes five checkouts in the terminal, and says he is using the desktop app more because it creates the worktrees for him. Both can be true. The terminal habit and the app habit are different tools.
  • He tells you not to copy the setup as law (33:13). A page that turns his five tabs into a required number has already disagreed with him.
