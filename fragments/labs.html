Run the labs

Run the command from the guide directory, next to index.html. Use Python 3.10 or later. The recorded tests used CPython 3.14.7 on arm64 macOS.

python3 -B labs/replay.py lab-output

Use a new output path for each full replay. Use a different output path if you also run a lab on its own. The labs use the Python standard library and synthetic data. They need no network or API key.

The replay runs seven commands in each of two fresh directories. It checks each exit code and compares SHA-256 hashes for five generated files. Inspect the recorded commands, output, and file hashes and the replay script.

Lab 1. Change a Python invoice service

Keep the original API call valid. Add an optional discount in cents. Deduct the discount before tax, cap the taxable amount at zero, and round tax up at half a cent.

Use the example tax rate of 8.25%. The test contract requires exact results for large values and rejects negative amounts, fractions, and Boolean values.

LAB_BASELINE=1 python3 -B -m unittest discover -s labs/service
python3 -B -m unittest discover -s labs/service

Expect exit 1 for the original service. Expect exit 0 and eight passing tests for the updated service. The original service had two incorrect totals and five unsupported discount cases in each trial.

  1. Worked example. Apply the discount to a 300-cent subtotal. A discount of 100 cents leaves 200 cents taxable. The rate gives 16.5 cents in tax. The service rounds the tax to 17 cents and returns 217 cents. The original function returns 216 cents for the equivalent 200-cent subtotal.
  2. Partial task. Copy the baseline into a scratch file. Add the optional argument and the discount calculation. Make the discount tests pass first. Then replace the tax expression with integer arithmetic.
  3. Independent task. Add a case for a discount equal to the subtotal. Predict its result, run the test, and explain why the API still accepts calls with one argument.
  4. Recall. Which test distinguishes exact arithmetic from a float conversion at large values?
  5. Transfer. Write the acceptance checks for an order API with a delivery charge. State whether the charge enters the taxable amount before you write code.
  6. Delayed check. Tomorrow, recreate the 200-cent regression test from the rule. Compare your result with the original and updated functions.
Check your answers

Tax in cents equals (taxable cents × 825 + 5,000) divided by 10,000 with integer floor division. A discount equal to the subtotal gives zero. The large-value test supplies 10²⁰ + 200 cents and expects 108,250,000,000,000,000,217 cents.

Lab 2. Test a classifier under a data shift

Fit a one-threshold sensor rule on 200 training rows per seed. Evaluate it on 100 ordinary test rows and 100 shifted test rows. Use seeds 7, 19, and 43.

Use the training majority label as the baseline. The full rule uses the badge near the threshold and the sensor elsewhere. The ablation removes the badge and applies the same fitted sensor threshold everywhere.

The generator makes the badge match the label with probability 0.96 on the training and ordinary test splits. It uses probability 0.12 on the shifted split. The sensor generator stays the same.

The checks defined before the run require three results on each seed. The full rule must beat the ablation on the ordinary split. The ablation must beat both alternatives on the shifted split.

Reference workflow loop

The report workflow is a typed state machine with no model calls. A Python dataclass holds the task state. Two typed tool interfaces accept a source reader and a draft writer. The stage determines the next operation. A model could propose an action, but the policy would still check its arguments, budget and permissions.

Task stages and completion checks
StageActionNext stage
readValidate and extract the local source rows.draft with validated rows in the checkpoint.
draftRender the report and verify its exact content on disk.review after successful verification.
reviewStop for a human. Verify the draft on restart.draft if the draft needs repair and budget remains.
failedStop and retain the diagnostic events.Terminal for that checkpoint.

The loop caps inputs at 16,384 bytes and 100 rows. It allows at most four tool calls and one retry per task. It saves the incremented call count before each tool call.

The task fingerprint binds the checkpoint to the input bytes and recipe version. The writer replaces the output file atomically. If a crash follows the write, the restart checks the existing file before it attempts another write.

A successful restart with an intact draft adds zero calls and makes no file change. The normal run uses two calls. A run with one injected transient read failure uses three calls and one retry.

Eight tests passed in each trial. They cover draft quality, a transient failure, a persistent failure, a crash after write, a missing draft or invalid UTF-8 bytes, a silent writer, invalid or changed input, and excess source size.

Run one process per output directory. The local checkpoint is trusted code input. The loop has no concurrent writer lock, hard timeout for a hung tool, or external delivery step.

  1. Worked example. The crash test stops execution after the writer saves the draft. The next run reads the prior checkpoint, verifies the draft, and reaches review without another write.
  2. Partial task. Read the transient-failure test. Implement a writer stub that fails once, then succeeds. Check the final stage, retry count, and artifact content.
  3. Independent task. Define a test for a write that reports success but leaves truncated content. Run it and check that the workflow does not reach review.
  4. Recall. What must be true on disk before the loop reaches review?
  5. Transfer. Design a checkpoint and completion test for a dataset export. Identify the human decision before any delivery step.
  6. Delayed check. Next week, draw the four stages from memory. Predict the result of two consecutive transient failures.
Check your answers

The draft must exist and match the exact rendered content. Two consecutive tool failures end the task at failed. The first consumes the only retry.
